## ۲. موجودی دقیق محتوای فعال

### کتاب‌ها: ۳ رکورد

| شناسه پایدار فعلی | عنوان | نویسنده | تجربه‌های مرتبط |
|---|---|---|---|

فهرست پادکست‌ها همان چهار تجربه `voice, begin, pause, another` با `format=listen` است، نه یک کاتالوگ صوتی مستقل. تابع `player` اعلام می‌کند فایل صوتی هنوز اضافه نشده و حرکت پلیر بدون صداست. پس ۴ عنوان شنیداری داریم، اما ۴ فایل صوتی تأییدشده نداریم.

### جهان‌ها و دالان‌ها

۵ جهان: `solitude` جهان تنهایی، `choice` جهان انتخاب، `memory` جهان خاطره، `beginning` جهان آغاز، `home` جهان خانه.

فیلدهای جهان: عنوان، kicker، توضیح، mood و کلمات. تجربه‌های یک جهان از جهان اصلی یا پیوند کلمات انتخاب می‌شوند و لایه فعلی حداکثر ۴ مورد نشان می‌دهد.

۴ حال‌وهوا/دالان: `calm` مکث و آرامش / دالان مکث؛ `think` یک فکر تازه / دالان پرسش؛ `imagine` کمی خیال / دالان خیال؛ `change` شروع دوباره / دالان آغاز.

فیلدهای mood: label، short، title، icon، verb، subtitle، invitation و world. صفحه «دالان‌ها» همین ۴ mood را نمایش می‌دهد، نه فهرست مستقیم ۵ جهان. این دو مدل نباید یکی شوند.

### Collections و داده‌های قدیمی

در مسیر زنده هیچ collection مستقل دیده نمی‌شود. `lib/mock-data.ts` سه collection قدیمی دارد: «ادبیات کلاسیک فارسی»، «فلسفه و اندیشه»، «داستان‌های عاشقانه» با آمار ثابت ۲۴، ۱۸ و ۱۵. این اعداد، تعداد رکورد واقعیِ تأییدشده نیستند. همچنین ۵ کتاب، ۵ تجربه، ۴ جهان و ۶ mood قدیمی در همان فایل هستند. اجزای React قدیمی به آن‌ها اشاره می‌کنند اما Home فعلی آن‌ها را mount نمی‌کند.

این داده‌ها باید در آرشیو migration حفظ شوند؛ به‌صورت خودکار منتشر نشوند و با سه کتاب فعلی ادغام نشوند. Collections در پنل به‌عنوان قابلیت جدید با حالت draft شروع می‌شود؛ انتشار در سایت مستلزم اتصال renderer و تعیین محل نمایش است.

## ۴. تمام محل‌های جلد کتاب

چهار محل فعال از تابع مشترک `cover(b)` استفاده می‌کنند:

1. کتاب شناور Home: `home()`، حوالی خط ۳۲۳.
2. کارت‌های کاروسل دورنمای دالان‌ها: `perspectiveCarousel()`، حوالی خط ۳۱۵؛ چند تجربه می‌توانند جلد یک کتاب را تکرار کنند.
3. قفسه صفحه کتاب‌ها: `booksScreen()`، حوالی خط ۳۴۸.
4. لایه جزئیات کتاب، از هر مسیری که باز شود: `bookLayer()`، حوالی خط ۳۵۴.

در صفحه عکس‌ها، دکمه کتاب را باز می‌کند؛ خود کارت عکس جلد نیست. نتایج جست‌وجو، کارت ذخیره‌شده، مسیر پیشنهادی و کتابِ پشت تجربه فعلاً نام کتاب را نشان می‌دهند، نه یک جلد مستقل.

در اجزای غیرفعال React، `LayerSystem.tsx` هم جلد Book Layer و هم جلد کتاب‌های داخل World Layer را از `coverImage` می‌گیرد؛ در صورت فعال‌سازی مجدد باید به همان منبع مرکزی متصل شود. تصویر Experience و کاور پلیر قدیمی نباید خودکار جلد کتاب فرض شوند.

راه‌حل: یک `Book.coverMediaId` و renderer مشترک. اگر فایل تعیین نشده، خروجی فعلی CSS/title/author با `tone` حفظ شود. تعویض جلد در یک تراکنش، نسخه جدید مدیا و ارجاع کتاب را ثبت و تمام چهار محل را به‌روز کند. کلید فایل تغییر کند تا cache جلد قبلی باقی نماند. alt و crop/focal point در پنل قابل‌ویرایش باشند.

## ۵. مدل داده پیشنهادی

مدل فعلی Prisma شامل User، AuthSession، OAuthAccount، Author، Book، Chapter، AudioTrack، UserLibrary، Subscription و Payment است. داشتن schema اثبات فعال‌بودن تمام قابلیت‌های آن نیست. مدل‌های editorial زیر باید افزوده یا تکمیل شوند:

| مدل | فیلدها / رابطه‌های اصلی |
|---|---|
| ContentEntity / ContentRevision | id، نوع، legacyKey، slug، draftRevisionId، publishedRevisionId، version، زمان‌ها، deletedAt؛ نسخه محتوایی immutable با schemaVersion |
| Author | نام و شرح فعلی؛ تصویر اختیاری و ترتیب؛ اتصال به Book فعلی |
| Book | عنوان، authorId، lead، description، keywords، coverMediaId، legacyTone؛ نگهداری UUID دیتابیس و نگاشت prince/stranger/house |
| Experience | عنوان، short، paragraphs مرتب، question، bookId، primaryWorldId، format، minutes، audioMediaId، artworkMediaId و editorialNote |
| ExperienceMood / ExperienceWorldLink | چند mood؛ پیوندهای مرتب label → worldId؛ حفظ معنا و ترتیب words فعلی |
| Mood | فیلدهای فعلی، آیکن از allowlist، worldId و position |
| World | عنوان، kicker، description، moodId، keywords؛ مدیای اختیاری و انتخاب مرتب تجربه‌ها |
| Collection / CollectionItem | عنوان، slug، توضیح، coverMediaId؛ item با نوع book/experience/world و دقیقاً یک رابطه معتبر، position |
| PhotoEditorial | عنوان، توضیح، bookId/worldId اختیاری، imageMediaId اختیاری، legacyStyle و مقصد معتبر |
| MemberWork | kind=writing/image/podcast، عنوان، متن، summary، authorDisplay، userId اختیاری، worldId، mediaId؛ reviewStatus جدا از publicationStatus |

| CommunityVoice | متن، authorDisplay، worldId، editorial، کیفیت تحریریه، legacyAgeHours؛ پیش‌فرض غیرفعال |

ساختار فیزیکی revisionها و روابط باید با migration واقعی هماهنگ شود؛ رابطه‌های نسخه منتشرشده نباید از draft جدید خوانده شوند. ویرایش رکورد منتشرشده یک draft جدید می‌سازد و نسخه live تا انتشار بعدی ثابت می‌ماند. وضعیت‌های انتشار: draft/published/archived؛ soft delete جداست. بررسی آثار: pending/approved/rejected. انتشار اثر عضو فقط پس از approval.

پادکست تحریریه فعلی همان Experience صوتی باقی بماند؛ ساخت مدل مستقل Podcast در این مرحله لازم نیست. Chapter و AudioTrack موجود برای فصل‌های کتاب حفظ شوند و اگر محتوای واقعی داشتند از پنل کتاب مدیریت شوند؛ اکنون شمار فصل‌ها/فایل‌های دیتابیس تأیید نشده است.

## ۶. ساختار پنل مستقل

یک برنامه مستقل `nahanja-admin` با deployment جدا، احراز هویت مدیران و API سمت سرور پیشنهاد می‌شود. frontend عمومی نهان‌جا ظاهر فعلی را حفظ می‌کند و کاتالوگ نسخه‌بندی‌شده منتشرشده را می‌خواند. دیتابیس PostgreSQL/Prisma موجود قابل توسعه است؛ انتخاب نهایی storage پس از بررسی اتصال‌های واقعی محیط انجام شود.

صفحات پنل:

1. داشبورد: draftها، آثار منتظر بررسی، خطاهای مدیا و آخرین انتشار.
2. کتاب‌ها: فهرست/جست‌وجو، ویرایش، تعویض جلد با پیش‌نمایش چهار محل، نویسنده، تجربه‌های مرتبط و فصل‌ها.
3. تجربه‌ها: ویرایش متن، سؤال، پیوندهای جهان، mood، کتاب و فایل صوتی؛ تب «پادکست‌های تحریریه» فیلتر همین فهرست.
4. جهان‌ها و حال‌وهواها: دو بخش جدا با رابطه روشن و ترتیب نمایش.
5. Collections: draftهای جدید و آرشیو legacy؛ اعضای مرتب و preview قبل از فعال‌سازی در سایت.
6. عکس‌ها: سه جایگاه فعلی، آپلود/جایگزینی، عنوان، متن و مقصد.
7. سهم تو: بررسی آثار، جزئیات، نسخه‌ها، تأیید/رد و انتخاب محل انتشار؛ ویترین Home جداگانه قابل تنظیم.
8. کتابخانه مدیا: تصویر/صوت/ویدئو، آپلود، metadata، وضعیت پردازش، فهرست محل مصرف و جایگزینی.
9. Home: نمایش preset فعلی، روشن/خاموش‌کردن سکشن‌ها، ترتیب کاروسل و ویترین، انتخاب تجربه/کتاب/جهان، preview دسکتاپ و موبایل.
10. صفحه‌ها و متن‌ها: Entry، Onboarding، درباره، همراهی، هدر، فوتر غیرفعال، UiCopy و SEO.
11. تاریخچه و زباله‌دان: diff، بازگردانی نسخه، بازیابی حذف و گزارش انتشار.
12. مدیران و دسترسی‌ها: فقط owner؛ هیچ عضو عادی با ثبت‌نام عمومی مدیر نمی‌شود.

در تمام فهرست‌های محتوایی، create/edit/trash/restore، جست‌وجو، فیلتر وضعیت، ترتیب و مشاهده محل مصرف وجود داشته باشد. صفحه ویرایش شامل ذخیره draft، preview، انتشار و لغو انتشار است. اطلاعات خصوصی یادداشت‌ها، bookmarkها و مسیرهای کاربران جزو محتوای تحریریه نیستند و نباید به پنل editorial منتقل شوند.

## ۷. API و permissions پیشنهادی

این endpointها قرارداد پیشنهادی‌اند و هنوز پیاده‌سازی نشده‌اند:

| مسیر | رفتار |
|---|---|
| GET /api/admin/{resource} | فهرست صفحه‌بندی‌شده، query، status و sort؛ resource از allowlist |
| POST /api/admin/{resource} | ایجاد draft؛ اعتبارسنجی schema و رابطه‌ها |
| GET/PATCH/DELETE /api/admin/{resource}/{id} | خواندن، ذخیره draft با version، soft delete |
| POST …/{id}/restore | بازیابی با اعتبارسنجی مجدد روابط |
| GET …/{id}/revisions | تاریخچه نسخه‌ها |
| POST …/{id}/publish و /unpublish | انتشار snapshot یا برداشتن از live؛ بررسی وابستگی‌های منتشرشده |
| POST …/{id}/rollback | ساخت revision جدید از نسخه قبلی؛ سابقه تغییر پاک نشود |
| POST …/reorder | فهرست کامل شناسه‌های همان container همراه expectedVersion؛ تراکنش اتمیک |
| GET …/{id}/usage | محل مصرف پیش از حذف یا تعویض مدیا |
| POST /api/admin/media/uploads | مجوز آپلود کوتاه‌مدت و محدود به فایل/نوع/اندازه |
| POST /api/admin/media/uploads/{id}/complete | بررسی واقعی فایل و ثبت مدیا پس از پردازش؛ صرف ادعای کلاینت کافی نیست |
| POST /api/admin/member-works/{id}/review | approve/reject با دلیل و audit |
| POST /api/admin/previews | ساخت preview کوتاه‌مدت، محدود به revision/release |
| GET /api/content/v1/catalog | فقط آخرین release منتشرشده، ETag و schemaVersion |
| GET /api/content/v1/home | Home همان release با روابط resolveشده |
| GET /api/content/v1/preview | فقط نشست preview معتبر، no-store؛ بدون دسترسی عمومی به draft |

منابع CRUD: books، authors، experiences، worlds، moods، collections، photos، member-works، community-voices، home-sections، pages و ui-copy. فصل و ترک صوتی زیر کتاب مربوط مدیریت شوند. خطاهای قراردادی: 401 بدون ورود، 403 بدون مجوز، 404 نبود/عدم دسترسی، 409 تعارض نسخه یا وابستگی، 422 داده نامعتبر.

| نقش | اختیار |
|---|---|
| Viewer | خواندن محتوای تحریریه و preview مجاز؛ بدون تغییر |
| Editor | ساخت/ویرایش draft، آپلود، تنظیم ترتیب draft؛ بدون انتشار یا مدیریت نقش |
| Publisher | اختیار Editor و انتشار/لغو انتشار/زباله‌دان و بازیابی |
| Moderator | خواندن و بررسی آثار ارسالی؛ تأیید به‌تنهایی مجوز انتشار نیست |
| Owner | مدیریت نقش‌ها، تنظیمات حساس و سیاست نگهداری؛ همه عملیات محتوایی با audit |

مجوز روی سرور در هر endpoint و سطح object بررسی شود. کوکی مدیریتی مستقل HttpOnly/Secure، حفاظت CSRF/Origin و محدودیت نرخ ضروری است. نشست عضو عادی `nahanja_member` مجوز مدیریت نیست. محتوا به‌صورت متن یا بلوک‌های معتبر رندر و escape شود؛ templateهای فعلی در همه فیلدها escape یکسان ندارند و نباید مستقیماً داده قابل‌ویرایش مدیر را در innerHTML بگذارند.

فایل در storage پایدار نگهداری شود، نه دیسک موقت Vercel یا localStorage. نوع واقعی فایل، اندازه و ابعاد/مدت کنترل شوند؛ SVG/HTML اجرایی ورودی آزاد نباشد. حذف فایلِ در حال استفاده مسدود شود. جایگزینی یک مصرف با جایگزینی سراسری مدیا دو عمل جدا باشند و پنل محل‌های تأثیر را نشان دهد.

برای preview از snapshot مشخص با نشست کوتاه‌مدت و مصرف یک‌باره بلیت اولیه استفاده شود؛ token پایدار در URL عمومی یا log نماند. محدودیت SAMEORIGIN فعلی اجازه iframe از دامنه مستقل Admin را نمی‌دهد؛ پیش‌نمایش ابتدا در تب سایت عمومی باز شود. برای preview داخل پنل، سیاست frame-ancestors باید صریحاً فقط origin پنل را مجاز کند، نه wildcard.

## ۸. حفظ محتوا و مسیر اجرای بعدی

۱. snapshot همراه این سند را مبنا قرار دهید. شناسه‌های فعلی و ترتیب و تمام پاراگراف‌ها حفظ شده‌اند. فایل‌های کد این commit نیز مرجع متن‌های قالب، سبک جلد و داده‌های غیرفعال‌اند. به‌جای بازنویسی پیش‌فرض‌ها، import دارای legacyKey یکتا و قابلیت اجرای دوباره ساخته شود.

۲. با دسترسی احرازشده Vercel، فقط وجود و scope متغیرهای DATABASE_URL، DATABASE_URL_UNPOOLED، AUTH_PUBLIC_ORIGIN و اتصال storage بررسی شود؛ مقدار secrets در گزارش یا کد قرار نگیرد. env.example فعلی کامل‌بودن production را ثابت نمی‌کند. rewrite فعلی /member-api به سرویس Railway باید در اتصال پنل لحاظ شود.

۳. ابتدا backup و migration افزایشی در محیط staging؛ خواندن شمار واقعی Book/Author/Chapter/AudioTrack. نگاشت legacyKey به UUID موجود، بدون تطبیق صرفاً با عنوان و بدون دست‌زدن به users، payments یا subscriptions.

۴. import کاتالوگ فعال با وضعیت منتشرشده برای حفظ نمایش فعلی، بدون ساخت فایل صوتی/تصویر فرضی. داده‌های غیرفعال در آرشیو جدا؛ سه collection قدیمی unpublished. هر اجرا فقط موارد importنشده را اضافه کند و ویرایش بعدی مدیر را overwrite نکند.

۵. API کاتالوگ و adapter در HTML فعلی ساخته شود. release کامل با روابط معتبر بارگیری شود و rendererهای فعلی آن را مصرف کنند. fallback تنها هنگام خطای کل دریافت به آخرین release سالم باشد؛ نبودن یک رکورد در release موفق نباید باعث بازگشت رکورد حذف‌شده از defaults شود.

۶. اول CRUD کتاب/جلد/تجربه و مدیا، سپس جهان/mood/عکس/سهم تو و بعد مدیریت Home و متن‌ها. authentication مدیریتی، draft و publish باید از ابتدا همراه API باشند، نه بعد از رابط.

۷. تست پذیرش: تغییر یک جلد در هر چهار محل؛ تغییر عنوان/متن در جست‌وجو و لایه‌ها؛ فایل واقعی قابل پخش؛ draft نامرئی برای عموم؛ preview دقیق؛ انتشار release بدون مخلوط‌شدن نسخه‌ها؛ حفظ ترتیب؛ تعارض ویرایش هم‌زمان؛ حذف دارای وابستگی؛ بازیابی؛ جلوگیری از XSS، آپلود نامعتبر و دسترسی عضو عادی؛ حفظ نمایش فعلی در دسکتاپ و موبایل.

۸. پس از تطبیق staging با snapshot، اتصال production و امکان rollback به release قبلی. ساخت UI پنل به‌تنهایی معیار اتمام نیست؛ تغییر آزمایشیِ قابل‌بازیابی در پنل باید در سایت واقعی دیده شود.
